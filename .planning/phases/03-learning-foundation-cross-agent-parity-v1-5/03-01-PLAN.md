# Plan 03-01: Atomic Lockfile & Counter Split Parity in Rust Core

## Objective
Port the robust atomic `_LockFile` implementation from `ace.py` into `src/ace.rs` with `{pid}:{hostname}:{timestamp}:{nonce}`, dead-process stale lock reclamation, foreign host safety, and verify concurrent multi-process writer safety in both Rust and Python.

## Context
In Milestone 1, Python `ace.py` received atomic lockfile recovery (F9 / G3) and counter decoupling (F8 / G4). However, the Rust core (`src/ace.rs`) currently uses direct file replacement (`fs::rename`) without acquiring an advisory `.lock` file. For multi-agent setups (e.g. Claude Code + Codex + Antigravity running simultaneously), concurrent `hive ace apply` calls in Rust would experience lost updates.

## Tasks

<task id="03-01-01" type="tracer">
### Task 1: Rust Atomic `LockFile` Implementation
- In `src/ace.rs`:
  - Implement `LockFile` struct wrapping `lock_path = path.with_extension("lock")`.
  - Use `std::fs::OpenOptions::new().write(true).create_new(true)` (`O_EXCL`) for atomic creation.
  - Payload format: `{pid}:{hostname}:{iso_timestamp}:{nonce}`.
  - Implement retry loop with timeout (default: 10s) and sleep jitter.
  - Implement stale lock recovery:
    - If acquisition fails, read existing lockfile payload.
    - If `hostname` matches local host, check if process `pid` is active:
      - Windows: `OpenProcess` via `windows-sys` or stdlib process inspect.
      - Unix: `kill(pid, 0)`.
    - If process is dead and lock age > 30s, unlink stale lock and steal.
    - If `hostname` differs, refuse steal and return structured error.
  - Wrap `ace::save` and `ace::apply` with `LockFile` guard (RAII drop removes lock).
</task>

<task id="03-01-02" type="expansion">
### Task 2: Standardize Datetime Deprecation & Strict Parity
- In `ace.py`:
  - Replace deprecated `datetime.datetime.utcnow()` with `datetime.datetime.now(datetime.timezone.utc)`.
- Ensure exact counter split parity (`seen`, `helpful`, `harmful`) across both implementations:
  - Jaccard duplicate match increments `seen` only.
  - Missing `seen` during legacy migration defaults to `helpful + harmful`.
</task>

<task id="03-01-03" type="expansion">
### Task 3: Concurrency Stress Test Suite
- Port `test_ace_concurrency.py` cases to Rust in `tests/integration_tests.rs`:
  - `test_rust_concurrent_writers_no_lost_updates`: 2 concurrent threads/processes × 25 applies preserve all bullets without loss.
  - `test_rust_stale_lockfile_recovery_dead_pid`: verifies reclamation after crashed holder.
  - `test_rust_foreign_host_lock_refused`: verifies NFS/foreign host refusal.
</task>
