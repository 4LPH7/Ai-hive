# Plan 02-02: Unified Config Hierarchy & Hash-Verified Refresh

## Objective
Implement hierarchical configuration resolution (CLI flags → ENV variables → `config.toml` → OS defaults) and hash-verified incremental indexing (`(size, mtime)` fast-path + SHA-256 confirm on change) across Python and Rust cores.

## Context
F6 revealed hardcoded drive paths (`D:\`) causing portability friction on macOS/Linux. F7 revealed that `mtime`-preserving git checkouts or cloud sync skips reindexing modified notes. This plan resolves both invariants.

## Tasks

<task id="02-02-01" type="expansion">
### Task 1: Hierarchical Config Resolution (CONF-01)
- Implement unified config loader in `src/common.rs` and `hive.py`:
  - Precedence 1: CLI flags (`--vault <path>`, `--projects <path>`, `--db <path>`).
  - Precedence 2: Environment variables (`HIVE_VAULT`, `HIVE_PROJECTS`, `HIVE_DB`).
  - Precedence 3: User config file (`~/.config/hive/config.toml` or `%APPDATA%/hive/config.toml`).
  - Precedence 4: Platform defaults (`D:\Valut\OBS` on Windows if exists else `~/Documents/Vault`, `%LOCALAPPDATA%/hive/hive.sqlite` on Windows, `~/.cache/hive/hive.sqlite` on Linux/macOS).
- Add `--config <path>` override support.
</task>

<task id="02-02-02" type="expansion">
### Task 2: Hash-Verified Incremental Refresh (SYNC-01)
- In `Index.refresh()` (both `src/index.rs` and `hive.py`):
  - Fast path: check `(size, mtime)` against SQLite `notes` table.
  - If `(size, mtime)` differs: compute SHA-256 of note content.
  - If SHA-256 matches existing stored hash: update `mtime` and `size` in `notes` table, but SKIP expensive re-tokenization / FTS5 rebuild!
  - If SHA-256 differs: re-parse frontmatter, update `notes`, and re-index in `notes_fts`.
- Update SQLite `notes` table schema (user_version = 4) to store `size INTEGER, sha256 TEXT`.
</task>

<task id="02-02-03" type="expansion">
### Task 3: Regression Tests for Config & Hash-Verified Refresh
- Author tests verifying:
  - CLI flag overrides environment variable, which overrides `config.toml`.
  - Mtime touch without content change triggers hash match fast-skip (no FTS reindex).
  - Content edit with preserved mtime triggers SHA-256 detection and reindexes cleanly.
</task>
