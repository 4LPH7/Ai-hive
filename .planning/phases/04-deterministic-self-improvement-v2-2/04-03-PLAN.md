# Plan 04-03: Time Decay & Symbol-Anchored ADR Staleness

## Objective
Implement time-based score decay for inactive playbook bullets and symbol-anchored staleness checks cross-referencing ADR notes against `graphify` code manifests.

## Context
Playbook bullets that were useful months ago may become obsolete as architectural patterns shift. Similarly, ADR notes that reference specific symbols, functions, or modules become stale when those symbols are refactored or deleted. This plan connects `graphify-out/manifest.json` and session mtimes directly into `hive lint` and `hive ace` to automatically flag stale documentation.

## Tasks

<task id="04-03-01" type="implementation">
### Task 1: Playbook Time Decay
- In `ace.py` and `src/ace.rs`:
  - When pruning or scoring bullets:
    - Bullets with `seen >= 10` but 0 helpful tags over `>30 days` receive net score penalty.
    - Bullets whose net score falls below prune threshold are pruned during `apply`.
</task>

<task id="04-03-02" type="implementation">
### Task 2: Symbol-Anchored ADR Staleness Lint
- In `lint.py` and `src/lint.rs`:
  - For ADR notes in `projects/<slug>/adrs/`:
    - Extract backlinked or code-quoted symbol names (e.g. `` `PlaybookLock` ``, `` `Index::search` ``).
    - Cross-check against repository's `graphify-out/manifest.json` or `graphify-out/graph.json`.
    - If a referenced core symbol was deleted or its defining file modified heavily since ADR creation, emit warning: `WARN adr-stale: ADR [[000X-...]] references symbol `XYZ` modified in commit ABC`.
</task>

<task id="04-03-03" type="testing">
### Task 3: Test Suite
- Author `test_decay_and_staleness.py`:
  - Test decay penalty on inactive bullets.
  - Test ADR lint staleness detector on modified/deleted code symbols.
</task>
